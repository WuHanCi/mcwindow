# 规划输入

输入是一个 JSON 对象。北京时间无时区输入默认 `+08:00`；建议显式写时区。可规划未来最多24小时。金额只能用整数分。

```json
{
  "source": "mcp",
  "now": "2026-10-23T11:50:00+08:00",
  "free_until": "2026-10-23T13:00:00+08:00",
  "budget_fen": 2500,
  "travel_minutes": 8,
  "queue_minutes": 6,
  "meal_minutes": 20,
  "buffer_minutes": 10,
  "strategy": "budget",
  "offers": []
}
```

- `source`：`mcp`、`manual`、`demo`。
- `strategy`：`budget` 按价格、返回时间排序；`time` 按返回时间、价格排序。
- `offers`：最多100个候选，各候选 `id` 必须唯一。
- 单程路程、排队、缓冲范围为0—120分钟，用餐为1—120分钟。

候选格式示例：

```json
{
  "id": "example-1",
  "name": "示例候选",
  "price_fen": null,
  "valid_from": "2026-10-23T00:00:00+08:00",
  "valid_to": "2026-10-23T23:59:00+08:00",
  "daily_windows": [["11:00", "14:00"]],
  "verified": false,
  "evidence": "对应查询工具及优惠信息摘录",
  "note": "门店、就餐方式、领取状态等需核对的条件"
}
```

`daily_windows` 可含多个区间，结束时间不晚于开始时间时视为跨午夜区间；空列表表示优惠有效期内无额外每日限制。可视页面编辑器支持单个每日时段，多时段可用 CLI 输入。

规划器采用左闭右开的优惠区间：点单时刻必须早于优惠结束。优惠仅须在点单时有效；餐后返回并完成缓冲必须不晚于下次安排。若某券要求在其他时点核销，须先把有效期保守收紧后再输入。

每个候选对应一次到店、一人一餐。路程、排队和用餐时间由用户填写；价格和适用条件确认后进入推荐列表。

此版本没有单独的星期枚举字段。若券面限制星期，先把候选的 `valid_from` / `valid_to` 裁剪到本次空档内允许的具体日期；跨日时拆分候选。星期限制按券面说明填写，日期和每日时段分别表达。
